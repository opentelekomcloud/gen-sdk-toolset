Only a user with the worker role can start, edit and confirm the grouping; a user with the viewer role sees it read-only, because this way the grouping follows the role model that the panel already uses: reading is available under require_viewer, changes require require_worker, and no new role in Zitadel is needed. A separate role for confirmation would add an approval step that the idea does not have: in the idea, the same user groups, edits and confirms the grouping.
