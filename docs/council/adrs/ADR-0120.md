The default SDK method name is built as follows: a base operation gets the name create, get, list, update or delete, a custom operation gets the name of the last constant URI segment, and for a nested path the constant segments after the first constant segment (after the version segment and path parameters) are appended to the name with "_", for example list_routes or tags_action. All default names within one resource are distinct: the rule that tells apart names that coincide, including for operations with different URIs, is defined before implementation based on data from all services. Operations of one resource that come from different documents with the same HTTP method and URI get no default name: the name stays empty until the user enters it, and resource generation does not start while any operation of the resource has no name. The same applies to operations whose default names still coincide after the rule that tells apart names is applied. The user can enter the same name to merge operations into one SDK method, because the base operation names match the create/get/list/update/delete functions of the services/vpc/v1/vpcs package in python-t-cloud, and the nested path segments tell apart operations on subcollections of one resource. Distinct default names keep operations from merging without the user: merging under ADR-0118 happens only when the user sets the same name. The HTTP method and URI cannot tell such documents apart, so an empty name leaves the choice to the user: different names or one name to merge them.
