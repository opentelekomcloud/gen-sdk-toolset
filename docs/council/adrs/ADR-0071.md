After a rescan, the grouping keeps the remaining endpoints in their resources, removes the ones that disappeared, and puts new ones in the "unassigned" list if they have an API version, or in the "no version" list if they do not, from where the user moves them into resources, because the user's manual work on the remaining endpoints is not lost on a rescan, and the system does not guess a resource for new endpoints. New endpoints go to the same "unassigned" and "no version" lists as in the preliminary grouping under ADR-0057 and ADR-0059. The user assigns them with the moves that ADR-0064 allows and does not need to run the grouping again, which ADR-0072 rules out.
