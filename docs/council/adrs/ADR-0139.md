The default SDK method name is built as follows. A basic operation gets the name create, get, list, update or delete, and a custom operation gets the name of the last static URI segment. For a nested path, the static URI segments after the first static segment (after the version segment and path parameters) are added to the name with “_”, wherever the segment that gave the resource its name is, for example list_routes or tags_action. In the name of a basic operation on an item, the last segment is singular, for example delete_tag. If PUT and PATCH on the same item would both get the name update, the PATCH operation gets the name patch. All default names within one resource are different. The rule that distinguishes clashing names, including those of operations with different URIs, is defined before implementation, based on data from all services. Operations of one resource from different documents with the same HTTP method and URI do not get a default name: the name stays empty until the user enters it, and resource generation does not start while any of its operations has no name. The same applies to operations whose default names still clash after the distinguishing rule is applied. The user can enter the same name to combine operations into one SDK method, because the starting point for counting segments does not depend on which segment the resource is named after, by the layout of ADR-0135 or by the user. So the rule works the same way for automatically and manually built resources, and the current code already builds names from the first static segment.
