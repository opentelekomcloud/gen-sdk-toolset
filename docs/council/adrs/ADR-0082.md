The service page and the grouping page open for any service from the /generation list, that is, for a service with endpoints in the active snapshot; if there is no grouping yet, the grouping page shows an empty state with a link to the service page; for any other repo both pages show PageNotFound, and the spec and result pages show PageNotFound for any service. If someone else's change makes the displayed object unavailable, the open page shows the same screen as when opening a direct URL (for example, PageNotFound for the service page and the grouping page); if the page has unsaved edits, this screen is shown only after clicking "Refresh" in the "Data changed" message, because the same access rule applies to an already open page and to a direct URL. So the user sees that the object is gone, rather than data that no longer exists in the system, and no separate state is needed for this case. Unsaved edits also do not disappear without a user action, as ADR-0083 requires.
