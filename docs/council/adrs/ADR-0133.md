Only a user with the worker role can change the operation kind and its SDK method name, and a user with the viewer role sees them read-only. Field types in the specification are also fixed only by a user with the worker role, and a user with the viewer role sees the problems and the selected types read-only. Only a user with the worker role can run, edit and confirm the layout, and a user with the viewer role sees the layout read-only, because the kind and method name, like field types and the layout, are generation inputs, and they are edited on the same page. So one access rule applies on the page: the modifying Generation routes are already protected by require_worker, and no new role in Zitadel is needed. The specification is reviewed and fixed by the same user, so the right to edit is not tied to who confirmed the resource.
