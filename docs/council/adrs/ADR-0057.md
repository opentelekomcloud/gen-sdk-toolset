Endpoints of the same API version go into one resource if their URIs have the same first constant segment after the version segment (if the URI has one) and after path parameters such as {project_id}. The resource name is this segment in lower case, with invalid characters replaced by "_"; if it does not start with a letter, the prefix "r_" is added. Endpoints whose segments give the same name go into one resource. Endpoints with no constant segment after the version go to the "unassigned" list, from where the user moves them into resources, because grouping by the first constant segment gives a small number of resources with short names. Such resources are close to the python-t-cloud packages of the form services/<service>/<version>/<resource>. Normalization makes the names valid under ADR-0065 right away. If the resource cannot be determined from the URL, the endpoint does not get an invented name, and the user assigns it manually under ADR-0064.
