While the page has unsaved edits, the panel does not change the data being edited but shows a "Data changed" message with a "Refresh" button; the button discards the edits and loads the current state. After a rescan, a saved grouping keeps the remaining endpoints in their resources and removes the ones that disappeared. New endpoints go to the "unassigned" list if they have an API version, or to the "no version" list if they do not, and from there the user moves them into resources, because the user learns about someone else's change without reloading the page, and their draft does not silently disappear: the user decides when to drop the edits and load the current state. Automatic merging with the draft would require storing the original version of the data, and the models currently have no shared revision and no updated_at fields; manual work on a saved grouping is still not lost on a rescan.
