In the current task, the /generation table shows only service names. Target columns and generation state chips are temporarily hidden. Existing state types do not change. State display comes back when real generation data is connected, because generation is out of scope (F3), so services from Scan have no per-target states, and columns and chips would be empty or misleading. This also matches the row contents from Q5 and does not require inventing a new state in `GenService` for data that does not exist yet.
