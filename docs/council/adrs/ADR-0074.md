The grouping is stored in new DB tables, separate from Scan data: `resource` (service, version, name, own id) and `resource_endpoint`, which links the service's endpoints to a resource, because a resource has its own id that does not change on rename, and each edit in the editor changes individual rows and does not touch the scan results. DB constraints check that a resource name is unique within a version and that an endpoint belongs to only one resource. If the grouping were stored as one JSONB document, these checks would exist only in code.
