When generation starts, the server saves with the job the model of the resource's operations and classes, built by the same function as the specification, and the generator creates code only from this model; at start the server rejects generation if the model has changed since the specification was shown (for example, by hash), and the page shows "Data changed" with a "Refresh" button, because the model is already built on the backend (ADR-0115), so the specification page and the generator use one function, and the model saved with the job records exactly what was generated, even if the data change after start. The check at start prevents generating what the user has not seen: an open page can lag behind the server by up to 15 seconds (ADR-0077), and the mismatch is found before generation, not in the finished package.
