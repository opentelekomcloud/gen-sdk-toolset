A nested field in the Entities section has a link to the table (document and anchor) its type comes from, at the commit of the active snapshot, because the link opens the version of the document that Scan parsed, since the scanner records the commit before reading the files. This way the user checks any suspicious field, not only a problem field, against the source table in one click. This is needed for two reasons: the parser normalizes types (date and timestamp become String, Map<K,V> becomes Object), and a nested table may be in another document and is found by a heuristic, so a matching error cannot be noticed without the link. If, under ADR-0096, a class merges structures from several documents, the field has a link to each source table.
