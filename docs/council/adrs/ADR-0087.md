The specification page opens for a confirmed resource of a service from the /generation list. For an existing but unconfirmed resource it shows the message “Resource not confirmed” with a link to the layout editor. For a resource that does not exist or a resource of another version it shows PageNotFound. The service page and the layout page open for any service from the /generation list, that is, for a service with endpoints in the active snapshot. If there is no layout yet, the layout page shows an empty state with a link to the service page. For any other repo both these pages show PageNotFound, and the result page shows PageNotFound for any service. If someone else's change makes the shown object unavailable, the open page shows the same screen as when opened by direct URL. If the page has unsaved edits, this screen is shown only after clicking “Refresh” in the “Data changed” message, because the specification shows exactly the resource contents that the user checked at confirmation (ADR-0068) and that the Generate button leads to (ADR-0086), and type fixes do not remove the confirmation (ADR-0110). A separate message with a link to the layout editor explains why an existing resource has no specification and what to do next; PageNotFound would confuse the user in this case.
