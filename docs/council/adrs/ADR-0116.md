The type of a problem field is stored in a separate DB table, one row per field: resource, field path, current type (empty after the selection is cleared), last action (selection, change, clearing), author from the server identity and server time. Each action overwrites the row, because one overwritten row per field stores exactly what ADR-0105 requires: the current type and the last action with author and time, including after the selection is cleared, and does not build up a log of all actions. The row is bound to the resource, like the fix scope in ADR-0108, and gives the server one current field value to compare by ADR-0113. The author is taken from the server identity, like initiated_by in Scan, and the time is taken on the server, so the client cannot fake them.
