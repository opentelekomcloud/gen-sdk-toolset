A basic operation gets the name create, get, list, update or delete, and a non-standard one gets the name of its last constant URI segment; for an operation on a nested path, the constant URI segments after the first constant segment (after the version segment and path parameters) are added to the name with "_", for example list_routes or tags_action. Method names within one resource must be different: the rule that tells apart operations with the same name, including ones with different URIs, is defined before implementation using data from all services, because the names of operations on the resource itself match the create/get/list/update/delete functions of the services/vpc/v1/vpcs package in python-t-cloud. Nested path segments tell apart operations of subcollections, which by ADR-0057 go into the same resource. The base name is built from the HTTP method and URI, like the list of operations by ADR-0089. So it does not depend on document titles or on the resource name and stays stable for the generation model by ADR-0114.
