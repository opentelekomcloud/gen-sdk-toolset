The service page and the grouping page open for any service in the /generation list, that is, any service with endpoints in the active snapshot. If there is no grouping yet, the grouping page shows an empty state with a link to the service page. For any other repo, both pages show PageNotFound, because access to both pages uses the same condition that puts a service in the /generation list. So following the link from the list under ADR-0053 never leads to a dead end, a direct URL behaves the same way, and one rule for both pages is easier to check. An empty state instead of a redirect keeps the address from ADR-0063 working and sends the user to the service page, where the preliminary grouping is started under ADR-0056. The spec and result pages still show PageNotFound for every service, because generation is not connected yet and they must not show mock data.
