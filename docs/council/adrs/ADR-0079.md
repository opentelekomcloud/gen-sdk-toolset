The panel shows any system state change on its own, whoever made it: scheduled discovery, CLI register-service or the backend itself, because what matters to the user is that the panel matches the data on the server, not who made the change. Discovery and CLI register-service change the set of services, has_api_ref and head_commit from a separate process without a Scan Job, and the backend moves unfinished jobs to failed on startup. The periodic refetch per ADR-0076 reads the current state from the server every time, so it catches such changes the same way as user actions, without a separate mechanism.
