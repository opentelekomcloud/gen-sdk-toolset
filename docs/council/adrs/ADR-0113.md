A request to fix a field passes the value the user saw: the selected type or no selection. If the server already has a different value recorded for the field, the server rejects the request, and the panel shows "Data changed" with a "Refresh" button, because a type selection is a decision of a specific person, with an author and a time (ADR-0105). Because of the refresh window of up to 15 seconds (ADR-0077) the user may not see someone else's selection, so it must not be silently overwritten. As with ADR-0083, the user learns about someone else's change and decides whether to repeat the selection. The current field value from ADR-0116 is enough for the check: no shared revision is needed, and no field lock that would have to be released.
